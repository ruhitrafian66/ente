# Ente Photos offline fork

Personal, Android-only fork of [ente-io/ente](https://github.com/ente-io/ente). The app shows on-device photos only, runs face recognition on device, and has no Ente account. Its only network use is the one-time download of the CLIP models, which the owner starts by hand (since 2026-11-25). Personal use only: do not assume anything here may be redistributed (see "Models").

- Fork: the owner's GitHub fork (remote `origin`; `git remote -v` shows it). Upstream: remote `upstream`. Work branch: `offline-faces`.
- Forked from upstream commit `6ace5d3` (2026-11-23), shallow clone (`--depth 1`).
- Target device: Samsung Galaxy S25 (arm64, Snapdragon 8 Elite, 12 GB RAM).
- Owner decisions so far are recorded under "Decisions". Do not reopen them without being asked.

## Layout

| Path | What |
|---|---|
| `mobile/apps/photos` | The Flutter app. All app work happens here. |
| `mobile/packages`, `mobile/apps/photos/plugins` | Shared Dart packages and app plugins (pub workspace rooted at `mobile/`). |
| `rust/` | Rust workspace. The app links `rust/bindings/frb/photos` through flutter_rust_bridge. ML lives in `rust/crates/ml`, image decode in `rust/crates/image`. |

| `mobile/apps/photos/docs/offline-fork-removal-plan.md` | Staged plan for the full removal of network and account code. Read it before removal work. |

Deleted from the fork: `web/ server/ desktop/ cli/ docs/ apple/ android/ architecture/`, most of `infra/`, `mobile/apps/auth`, `mobile/apps/locker` and the shared packages the app does not use. Unused Rust crates, apps and bindings are deleted too.

## Commands

Run from `mobile/apps/photos` unless noted.

```sh

./tool/fetch_bundled_ml_models.sh

# Dart deps (from mobile/). Do NOT pass --enforce-lockfile: the fork changed pubspec.
(cd ../.. && ~/development/flutter/bin/flutter pub get)

# Regenerate the Rust bridge (about 1 to 2 min now; exits 1 at the end because rustfmt is missing: harmless). Output: lib/src/rust and rust/bindings/frb/photos/src/frb_generated.rs (both git-ignored: a clean checkout needs this step)
(cd ../../../rust && PATH="$HOME/.cargo/bin:$HOME/development/flutter/bin:$PATH" cargo codegen frb photos)

# Gates
~/development/flutter/bin/flutter analyze --no-pub          # must print "No issues found!"
~/development/flutter/bin/flutter test --no-pub test/services

# Build (release, debug-signed when no keystore is configured). arm64 only.
~/development/flutter/bin/flutter build apk --release --flavor fdroid \
  --target-platform android-arm64
# -> build/app/outputs/flutter-apk/app-fdroid-release.apk (about 177 MB)
# Test build: add --dart-define=OFFLINE_FORK_LOGCAT=true so the app log reaches `adb logcat`
```

- Do NOT pass `--no-pub` to `flutter build`: the release plugin registrant is then not regenerated and the Java compile fails on dev-only plugins (`flutter_native_splash`, `integration_test`). `--no-pub` is fine for `analyze` and `test`.
- Build times on this Mac: first build about 25 min (Rust cross-compile with thin LTO); later builds with Rust cached 2.5 to 4 min.

- Flavor `fdroid` is the only one that builds: its applicationId is `io.ente.photos.offline`, label "Ente Offline". Keep `namespace "io.ente.photos"` (Dart refers to Kotlin classes by that name).
- `analysis_options` treats lints such as import ordering as errors. `dart fix --apply lib` fixes most of them.
- Check the merged manifest after a build: `aapt2 dump permissions <apk> | grep -iE "INTERNET|BILLING|NETWORK"` must show `INTERNET` only (since 2026-11-25, for the CLIP download), no `BILLING` and no `ACCESS_NETWORK_STATE`. `MANAGE_EXTERNAL_STORAGE` is expected too (since 2026-11-25).

## How the fork works

Upstream already had an account-free "local gallery" mode (`AppMode.localGallery`, `isLocalGalleryMode`). The fork forces that mode and fills its gaps.

- `lib/offline_fork.dart` holds the fork's constants (ML switches and tuning). Since removal stage 4.2 there is no `kOfflineFork` or `isLocalGalleryMode` any more: the local path is the only path. Remaining deviations are marked with a comment starting `Offline fork:`.
- **Mode**: `LocalSettings.appMode` always returns `localGallery`. First start goes straight to the photo permission screen (`GrantPermissionsWidget(startWithoutAccount: true)`), which also sets ML consent.
- **ML file ID**: ML data (face IDs, cluster maps, `PersonData.manuallyAssigned`) is keyed by an int. Upstream account mode uses `uploadedFileID`; local mode uses the int that `OfflineFilesDB` assigns per device `localID`. Use the synchronous getter `EnteFile.mlFileID` (`lib/models/file/extensions/file_props.dart`) in all people/face code. It reads an in-memory cache (`OfflineFilesDB.refreshIntIdCache()`, loaded at startup). `getMlFileIdToCreationTime()` in `lib/utils/ml_file_ids.dart` and `getFilesForMlFileIDs()` in `lib/utils/face/face_thumbnail_cache.dart` are the batch helpers. `uploadedFileID` is null or -1 for every file.
- **ML databases**: there is no account database. `MLDataDB.instance`, `DartMLDataDB.instance`, `RustMLDataDB.instance`, `FaceClustering.instance`, `ClipVectorDB.instance`, `ClusterCentroidVectorDB.instance` all resolve to their `localGalleryInstance` (`ente.ml.offline.db`).
- **Persons are local**: `EntityService.addOrUpdate/deleteEntry` write straight to the local `entities` table (in `FilesDB`), IDs `local_<nanoid>`, no keys, no gateway. `PersonService._syncOnce` only reconciles `PersonData.assigned` with the cluster-person table. `PersonService.mergePersons(sourceID, targetID)` is new (upstream cannot merge two named persons). Contact linking is off.
- **Models**: only the two face models ship in the APK (`assets/ml_models/`, git-ignored, fetched by the script): YOLOv5-face 640 and MobileFaceNet (192-d). `installBundledMlModels()` copies them to `<app support>/assets/models/<key>/<file>`, where the Rust asset store treats an existing file as downloaded. Pets and OCR are off (`kOfflineRunPets`, `kOfflineRunOcr`). CLIP: see the next item.
- **CLIP (magic search, Discover)**, added 2026-11-25, NOT run on a device: `kOfflineRunClip = true` only permits CLIP. The models are MobileCLIP-S2 from `models.ente.com` (Ente's own exports: image 143 MB, quantized text 67 MB, vocabulary 3 MB; catalog and sha256 in `rust/crates/ml/src/assets.rs`). They are not in the APK. `MLModelDownloadService` (`lib/services/machine_learning/ml_model_download_service.dart`) downloads them through the Rust `preloadMlModels` only after the owner taps "Magic search model" on the ML settings page (pref `offline_fork_clip_download_requested`; later runs continue the download; a failed try waits 10 minutes). Code must read `MLModelDownloadService.instance.isClipActive` (true when the files are on disk), never the constant: face indexing must keep working with no network. After the download the service loads the text model and triggers ML, which runs CLIP for the files that have faces indexed already. Search uses the brute-force scan (`kOfflineEnableVectorDb` is false). The index counter counts faces AND CLIP as soon as CLIP is active, so it drops after the download and rises again.
- **Videos**: face detection sees one 512 px thumbnail frame per video. Accepted limitation.
- **Network**: `INTERNET` is in the release manifest again since 2026-11-25, for the CLIP model download only (owner's decision). The Rust downloader (`rust/crates/assets`) is the only network code; its other users stay off (`LocationService.getLocationIndex` returns null, `kOfflineRunOcr`, `kOfflineRewind`, `kOfflineRunPets`). Do not enable one of them without the owner's request. Firebase, in-app purchase, install referrer and google-services were removed by running `scripts/prepare_fdroid_source.sh` once. Sentry, update checks, push, memory music and deep links are guarded off. WorkManager tasks no longer require a network.
- **S25 tuning**: XNNPACK threads 6 and ORT intra-op threads 4 (`rust/crates/ml/src/onnx/providers.rs`), thin LTO, arm64-only ABI, relaxed battery/temperature gates, warm ML sessions while in the foreground, larger indexing chunks. Execution provider order on Android: WebGPU, XNNPACK, CPU. Indexing is still one image at a time (`SuperIsolate` lock).
- **Flags**: `FlagService.internalUser` no longer returns true for debug builds, so debug and release use the same ML database backend (`rustMlDb` = false, the Dart DB).
- **New tools** (Settings > Free up space):
  - Exact duplicates: `lib/services/exact_duplicates/`, `lib/services/exact_duplicates_service.dart`, `lib/db/exact_duplicates_db.dart`, `lib/ui/tools/exact_duplicates_page.dart`. Size grouping, then SHA-256 of the origin file; never flags similar images.
  - Compress images (2026-11-25, NOT run on a device in this form). Owner's rule: "doesn't matter what format the image is in or what extension name it has, if the image is too big for its dimensions, then approve it for compression/conversion ... simplify the workflow". It replaces the two earlier tools "Convert PNG to JPG" and "Recompress large JPGs" (their screens and the PNG device service are deleted). Files: `lib/services/image_compress_core.dart` (pure logic), `image_compress_decode.dart` (dart:ui decode), `image_compress_service.dart`, `lib/ui/tools/image_compress_page.dart`, `image_scan_report_page.dart` (result per folder), `image_compress_single.dart` ("Compress" in the image viewer menu, value 13 in `file_app_bar.dart`, for every image), tests in `test/services/image_compress_core_test.dart`. `lib/services/png_to_jpg_core.dart` stays as a helper library (PNG header, transparency, JPEG dimensions, capture-time EXIF, `pickJpgName`); its `PngToJpgConverter` has no caller in the app any more and stays only with its tests.
    - One rule: an image of at least 300 kB with at least 4 bits per pixel is listed (a camera photo has 2 to 3.5). The format comes from the first bytes of the file (`sniffImageFormat`), never from the name or the Android media type. Supported: JPG, PNG, WebP, BMP (`kImageCompressFormats`). The viewer entry has no size and no ratio limit.
    - Not offered, with the reason on the page: other formats (GIF, HEIC/AVIF, TIFF), animated PNG/WebP, a JPEG with more than 64 kB after the end of the image (motion photo, HDR gain map, depth map), a JPEG with source quality below 92 (not applied to a file chosen in the viewer), CMYK, more than 40 MP, folders outside `DCIM/` and `Pictures/` unless "All files access" is granted.
    - Run: no quality selector. Encode with the Rust `decodeFullToJpeg` (upright, sRGB) at quality 90, fallback 95. A non-JPEG with a non-opaque pixel is kept as it is. Picture check for every format: the original and the copy are decoded with the engine decoder and compared (PSNR over RGB, minimum 40 dB). The copy is kept only if it is 25% smaller. Name: `<base>.jpg`, or `<base> (1).jpg` when that name is in use (a JPG source). A JPEG source keeps its EXIF segment byte for byte with the orientation tag set to 1; other sources get the capture time as EXIF. Originals are deleted in one batch at the end; a refused delete offers "delete again" or "remove the copies". Lists are sorted by MediaStore DATE_MODIFIED, newest first. One log line per result (`ImageCompressService.logResult`) and one "Image scan, <folder>: {...}" line per folder.
  - Compress videos (added 2026-11-25; owner's verdict after a device test on 2026-11-25: "the videos converted lost quite a lot of detail, so it seems its not worth doing"; the feature stays in the app but the owner will not use it; do not spend work on it unless asked). Lesson: a size tool needs a measured picture check, not only a bitrate rule. Details: `lib/services/video_compress_core.dart` (pure logic: bitrate rule, skip rules, state machine), `video_compress_service.dart`, `lib/ui/tools/video_compress_page.dart`, 29 tests in `test/services/video_compress_core_test.dart`. Native part: `VideoCompressor.kt` in `mobile/packages/native_video_editor` (methods `probeVideo` and `compressVideo`; media3 Transformer, hardware HEVC, VBR, audio copied, MP4 creation time and location written through `InAppMp4Muxer.MetadataProvider`). Same size, frame rate and audio; only the video bitrate goes down. Rule: target = 5 Mbit/s at 1080p30, scaled by pixels^0.75 and fps^0.5; an H.264 source below that target is skipped, and the target is at most 0.65 x the source; an HEVC/VP9/AV1 source needs 1.75 x the target. Skipped: HDR, more than 65 fps, extra tracks, folders outside `DCIM/`, `Movies/`, `Pictures/`. The copy is named `<name>_hevc.mp4`; it is kept only if it is 20% smaller and its codec, displayed size, duration, audio track count and frame count match; the original is deleted in one batch at the end. The service logs one "Encoded ..." line per file with the encode time (the performance record). All tuning constants are at the top of the core file and are estimates: calibrate them on the S25 (speed, real saving, picture check) before the owner uses the tool on the whole library.

## Decisions

- Personal use only. InsightFace weights (non-commercial licence) are acceptable.
- No identifying information in the repository (owner, 2026-11-25): never commit a device serial number, a personal name, an e-mail address, an account or user name, an absolute home path (`/Users/<name>/...`), a phone number, a location, or the name or content of one of the owner's files or folders. This applies to code, comments, documents, CLAUDE.md, test data and commit messages. Write "the owner", "the fork", `~` or a repository-relative path. Before each commit run `git diff --cached | grep -inE "/Users/|@[a-z0-9-]+\.[a-z]{2,}|serial"` and read the hits. On 2026-11-25 the owner asked for a history rewrite: the serial, the account name, the model variant and the home paths were removed from all commits (`git filter-branch`, then a force push), so every commit hash from before that day changed. The commit author name and e-mail stay as they are (owner's choice). A further history rewrite or force push needs a new explicit request.
- Planned second step, not started: SCRFD-10G detector + ArcFace R50 (`w600k_r50`, 512-d, from the InsightFace `buffalo_l` pack) behind a build option. Needs DB schema, vector index and cluster threshold changes, and a check that the detector's 5-landmark alignment matches. Do it after the removal.
- Video faces: one thumbnail frame per video is acceptable. No frame sampling.
- Full removal of network and account code was chosen over keeping it switched off ("Full removal" option: also upload, sync, server collections, keys, gateways). Follow `mobile/apps/photos/docs/offline-fork-removal-plan.md` stage by stage; `flutter analyze` must be clean after each stage. Keep the `EnteFile` fields and the `FilesDB` schema and migrations untouched (the plan explains why).
- Unused monorepo projects are deleted (done for top-level dirs; `mobile/apps/auth`, `mobile/apps/locker`, unused packages and Rust crates still to go).
- Person folder sort (requested 2026-11-24, in progress): a toggle, off by default, that MOVES images into `Pictures/People/<name>/`. Owner's choices: move, not copy; named persons only; images from all folders that Android lets the app move; a photo with several named persons goes to the folder of the largest face. Every move is recorded so "Restore all" can undo it. Since 2026-11-25 (owner reported "the app is skipping videos") videos move too: the device list uses `RequestType.common`, and a video from `Movies/...` returns to `Movies/...` on restore (`isVideo` in the planner). The first video build failed on the device list (duration filter, fixed in `22961af`). The video move is NOT yet verified on a device. Code: `lib/services/person_folders/`, `lib/db/person_folders_db.dart`, `lib/ui/tools/person_folders_page.dart`. Never run it on the owner's phone without an explicit request.
- CLIP (2026-11-25): the owner allowed a run-time download and the return of only the necessary network code. Model research of that day: no model is clearly better at the same cost. MobileCLIP2-S2 is a moderate gain (ImageNet 77.2 against 74.4, COCO R@1 48.8 against 45.4) with the same size, input, dimension and tokenizer, but only third-party ONNX exports exist (`AX1Y2JP/MobileCLIP2-S2-ONNX`, opset 23); a change touches the model catalog, the golden test and needs a re-index. SigLIP 2 B/16-256 is the option if multilingual search is necessary (768-d, new tokenizer, 650 to 940 MB, 2 to 4 days). The owner has not chosen one; MobileCLIP-S2 is in use. Never assume a search language from the owner's name; ask.
- Standing order of 2026-11-25 ("always push to github, build the apk, install the apk but leave the testing to me"): after each finished change, commit, push (fast-forward of `offline-faces` to `origin/main`), build the APK with the log option and install it with `adb install -r`, with no new request. Do not start or operate the app on the phone: the owner does the tests. Read logs with adb after the owner reports a test.
- The owner said to wait with the final APK until the removal is done. Test builds for the phone are wanted and were made.
- For complex subagent tasks use Fable 5.2 at medium or high effort. Start subagents one after the other on this Mac, and tell them not to run analyzer, tests, Gradle or cargo.

## Known gaps

- People pickers use `getAllFace(minClusterSize: ...)`; small named persons may be missing from the merge picker.
- A multi-person merge runs in sequence; a failure midway leaves a partial merge.
- The merge picker page title is the existing "Add to person" string.
- `showAddToPersonOption()` in `lib/models/gallery_type.dart` is false for device-folder galleries, so "Add to person" is missing there.
- Compress images: without "All files access" it cannot save outside `DCIM/` and `Pictures/` (MediaStore rule). The new file is a new MediaStore asset (new ML file ID): its faces are re-indexed, and manual face corrections for it are lost. XMP and the ICC profile are not copied (colours are converted to sRGB; a wide-gamut original loses gamut, and the summary counts these JPEG files). PSNR is a simple measure; the 40 dB limit is not calibrated on the owner's images, and it may keep more PNG screenshots unchanged than the old PNG tool did (that tool had no picture check). HEIC, GIF and TIFF are identified but not converted.
- Compress videos: the new file is a new MediaStore asset (new ML file ID, like PNG to JPG), and a Person folders move record for the original no longer matches. Originals and copies exist together until the run ends, so a large run needs free storage. There is no picture-quality measurement (no PSNR/SSIM check); quality rests on the bitrate rule.
- Exact duplicates hides upstream "large files" and "delete suggestions" (both need an account).
- About 20 files still open web links (`WebPage(`, `launchUrl`); they fail without `INTERNET`. The removal covers them.
- Without `INTERNET`, Android refuses all sockets, loopback included. A plugin that uses a localhost server (possibly video playback) would fail; not checked yet.

## History of this fork (for context)

1. Research showed upstream local gallery mode already detects and clusters faces but hides naming and merging behind sign-up banners, stores persons as encrypted server entities, and downloads models at run time.
2. Built in parallel by subagents: bundled models, local persons service layer, People UI, offline startup and Android config, S25 tuning, exact duplicates, PNG to JPG.
3. Parallel analyzers and builds exhausted the 8 GB Mac; the one-heavy-tool rule came from that.
4. Baseline APK built after two false starts (missing NDK 27, `--no-pub`), installed and partly tested on the S25.
